# 데이터베이스 시작

> MySQL에서 Database와 Table을 만들고 데이터를 다루기 전에 알아야 할 기본 개념을 정리했다.

## 1. MySQL에서 데이터를 저장하는 구조

MySQL을 사용할 때는 먼저 사용자 계정으로 **MySQL Server에 접속**한다.

접속한 뒤에는 실제로 사용할 **Database를 생성하고 선택**한 다음, 그 안에 **Table을 만들어 데이터를 저장**한다.

```text
MySQL Server
└─ Database
   └─ Table
```

MySQL에서는 `Database`와 `Schema`를 거의 같은 의미로 사용한다.

Database는 여러 Table을 포함하는 논리적인 저장 공간이고, Table은 실제 데이터를 일정한 구조에 맞춰 저장하는 단위다.

---

## 2. Database와 Table

Database를 생성했다고 해서 바로 모든 작업이 그 Database에서 수행되는 것은 아니다.

MySQL Server에는 여러 Database가 존재할 수 있기 때문에, 현재 어떤 Database를 대상으로 작업할 것인지 선택해야 한다.

그 이후 Table을 만들 때는 단순히 이름만 정하는 것이 아니라 다음과 같은 구조도 함께 정의한다.

- 어떤 Column이 필요한지
- 각 Column에는 어떤 종류의 데이터를 저장할지
- 각 Row를 어떻게 구분할지

즉 Table을 생성하는 과정은 **데이터를 저장하는 것이 아니라 데이터를 저장할 구조를 먼저 설계하는 과정**이다.

생성한 구조는 `DESC`로 확인할 수 있고, Database와 Table 목록은 `SHOW` 명령을 통해 확인할 수 있다.

반대로 `DROP`은 Table이나 Database의 구조 자체를 삭제한다. 내부 데이터도 함께 사라질 수 있기 때문에 특히 주의해서 사용해야 한다.

---

## 3. CRUD

Table을 만들고 나면 실제 데이터를 추가하고 조회하고 수정하고 삭제할 수 있다.

이 네 가지 기본 작업을 **CRUD**라고 한다.

```text
Create  → 데이터 생성
Read    → 데이터 조회
Update  → 데이터 수정
Delete  → 데이터 삭제
```

SQL에서는 각각 `INSERT`, `SELECT`, `UPDATE`, `DELETE`를 사용한다.

특히 `UPDATE`와 `DELETE`는 조건을 잘못 지정하면 의도하지 않은 여러 Row가 한 번에 변경되거나 삭제될 수 있다.

따라서 수정이나 삭제 작업에서는 **어떤 데이터를 대상으로 하는지 조건을 정확하게 확인하는 것이 중요하다.**

---

## 4. SQL

SQL(Structured Query Language)은 **관계형 Database를 다루기 위한 언어**다.

MySQL뿐만 아니라 Oracle, PostgreSQL 등 여러 관계형 DBMS에서 공통적으로 사용한다.

DBMS마다 세부적인 문법이나 추가 기능에는 차이가 있는데, 이러한 차이를 **Dialect(방언)**라고 한다.

SQL의 특징 중 하나는 처리 과정을 하나하나 구현하기보다 **어떤 결과가 필요한지 표현한다는 것**이다.

즉 애플리케이션에서 데이터를 어떤 순서로 탐색할지 직접 작성하는 것이 아니라, 필요한 데이터를 SQL로 요청하면 실제 처리 방법은 DBMS가 판단한다.

---

## 5. SQL 명령어의 종류

SQL은 목적에 따라 크게 네 가지로 구분할 수 있다.

| 분류 | 역할 | 대표 명령 |
| --- | --- | --- |
| DDL | Database와 Table 같은 구조를 정의 | `CREATE`, `ALTER`, `DROP` |
| DML | Table에 저장된 실제 데이터를 처리 | `INSERT`, `SELECT`, `UPDATE`, `DELETE` |
| DCL | 사용자 권한을 관리 | `GRANT`, `REVOKE` |
| TCL | Transaction을 관리 | `COMMIT`, `ROLLBACK` |

간단하게 다음과 같이 기억할 수 있다.

```text
DDL → 구조
DML → 데이터
DCL → 권한
TCL → 트랜잭션
```

## 6. 데이터 타입

Table의 각 Column에는 **어떤 종류의 데이터를 저장할 것인지 데이터 타입을 지정**한다.

데이터 타입을 나누는 이유는 단순히 숫자와 문자를 구분하기 위해서만은 아니다.

데이터의 특성에 맞는 타입을 사용하면 저장하려는 값의 의미를 명확하게 표현할 수 있고, 잘못된 형태의 데이터를 줄이며 저장 공간도 효율적으로 사용할 수 있다.

모든 타입의 범위나 크기를 외우기보다는 **어떤 상황에서 어떤 타입을 선택해야 하는지 이해하는 것이 중요하다.**

### 숫자 타입

정수는 값의 크기에 따라 여러 타입으로 나뉜다.

- `INT` : 일반적인 정수
- `BIGINT` : 더 큰 범위의 정수
- `DECIMAL` : 금액처럼 정확한 소수 계산이 필요한 값
- `FLOAT`, `DOUBLE` : 근사값을 사용하는 실수

`UNSIGNED`를 사용하면 음수를 사용하지 않는 대신 양수 범위를 더 넓게 사용할 수 있다.

---

### 문자열 타입

대표적으로 `VARCHAR`, `CHAR`, `TEXT`가 있다.

`VARCHAR`는 데이터의 실제 길이에 따라 공간을 사용하는 **가변 길이 문자열**이고, `CHAR`는 지정한 길이를 기준으로 사용하는 **고정 길이 문자열**이다.

```text
길이가 일정하지 않음 → VARCHAR
길이가 항상 일정함   → CHAR
```

이름, 이메일, 제목처럼 길이가 일정하지 않은 문자열은 대부분 `VARCHAR`를 사용한다.

`TEXT`는 게시글 본문이나 긴 설명처럼 비교적 긴 문자열을 저장할 때 사용한다.

---

### 날짜와 시간 타입

날짜와 시간을 저장할 때도 필요한 정보에 따라 타입을 선택한다.

- `DATE` : 날짜
- `TIME` : 시간
- `DATETIME` : 날짜 + 시간
- `TIMESTAMP` : 날짜 + 시간, Time Zone 변환 특성이 있음
- `YEAR` : 연도

`DATETIME`과 `TIMESTAMP`는 모두 날짜와 시간을 저장하지만 Time Zone 처리 방식에 차이가 있다.

`DATETIME`은 입력한 값을 그대로 저장하는 반면, `TIMESTAMP`는 Time Zone에 따라 값이 변환될 수 있다.
