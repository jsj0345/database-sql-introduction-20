## 1. 조회문의 출발점: 무엇을 어느 테이블에서 가져올 것인가

데이터를 읽을 때 기본이 되는 명령은 `SELECT`다.

내가 이해한 방식으로는 다음 두 부분을 먼저 생각하면 된다.

- `SELECT` : 결과에 보여줄 컬럼을 고른다.
- `FROM` : 데이터를 가져올 테이블을 정한다.

테이블의 모든 컬럼을 확인하고 싶다면 `*`를 사용할 수 있다.

```sql
SELECT *
FROM customers;
```

처음 데이터를 살펴보거나 테이블 구성을 빠르게 확인할 때는 편하지만, 항상 `*`를 사용하는 습관은 좋지 않을 수 있다.

예를 들어 실제로 필요한 값이 고객 이름과 이메일뿐이라면 굳이 비밀번호, 주소, 가입일 같은 다른 컬럼까지 함께 가져올 필요가 없다.

```sql
SELECT name, email
FROM customers;
```

내 기준에서는 `SELECT *`를 **전체 구조를 잠깐 확인할 때 편한 방식**, 필요한 컬럼을 직접 적는 방법을 **실제로 원하는 결과를 만드는 방식**으로 구분해서 기억했다.

필요한 컬럼만 지정하면 결과도 단순해지고, 불필요한 데이터를 읽거나 전달하는 양도 줄일 수 있다.

---

## 2. 결과에 보이는 컬럼 이름을 바꾸기

조회 결과를 그대로 보여주면 실제 테이블의 컬럼명이 출력된다.

개발할 때는 `name`, `email` 같은 이름이 자연스럽지만, 결과를 다른 사람이 볼 때는 의미가 바로 드러나지 않을 수도 있다.

이럴 때 `AS`를 이용해 결과 화면에서만 사용할 이름을 붙일 수 있다.

```sql
SELECT
    name AS 고객명,
    email AS 이메일
FROM customers;
```

여기서 중요한 점은 테이블의 실제 컬럼명이 바뀌는 것이 아니라는 것이다.

`AS`는 **조회 결과에 표시되는 이름을 임시로 바꾸는 기능**으로 이해하면 된다.

나중에 여러 테이블을 함께 조회하게 되면 비슷한 컬럼명이 겹칠 수 있는데, 이때도 별칭을 사용하면 결과의 의미를 구분하기 쉬워진다.

---

## 3. 전체 행이 아니라 필요한 행만 남기기

`SELECT`가 결과에 보여줄 **열(Column)**을 정한다면, `WHERE`는 어떤 **행(Row)**을 남길지 결정한다.

예를 들어 특정 이메일을 가진 고객만 찾고 싶다면 다음처럼 조건을 붙인다.

```sql
SELECT *
FROM customers
WHERE email = 'yisunsin@example.com';
```

가격이 일정 금액 이상인 상품만 확인하는 것도 같은 방식이다.

```sql
SELECT *
FROM products
WHERE price >= 10000;
```

조회 조건에서 자주 사용하는 비교 방식은 다음 정도로 정리할 수 있다.

| 표현 | 내가 이해한 의미 |
| --- | --- |
| `=` | 두 값이 같은지 확인 |
| `!=`, `<>` | 서로 다른 값인지 확인 |
| `>` | 기준보다 큰 값 |
| `<` | 기준보다 작은 값 |
| `>=` | 기준 이상 |
| `<=` | 기준 이하 |

결국 `WHERE`는 **테이블 전체를 대상으로 보지 않고, 조건을 통과한 데이터만 결과에 남기는 장치**라고 보면 된다.

---

## 4. 조건이 하나보다 많을 때

실제 조회에서는 조건 하나만 확인하는 경우보다 여러 조건을 묶는 경우가 많다.

이때 `AND`, `OR`, `NOT`을 사용한다.

### 모든 조건을 동시에 만족해야 하는 경우

가격도 기준 이상이고 재고도 충분한 상품만 찾고 싶다면 `AND`를 사용한다.

```sql
SELECT *
FROM products
WHERE price >= 5000
  AND stock_quantity >= 50;
```

`AND`는 연결한 조건이 모두 만족되어야 결과에 포함된다.

### 조건 중 하나만 만족해도 되는 경우

```sql
SELECT *
FROM products
WHERE price = 20000
   OR stock_quantity >= 100;
```

`OR`는 여러 조건 가운데 하나라도 맞으면 결과에 들어올 수 있다.

### 특정 조건을 제외하고 싶은 경우

```sql
SELECT *
FROM products
WHERE price != 20000;
```

내가 쿼리를 읽을 때는 복잡한 조건을 한 번에 해석하기보다는  
**각 조건을 따로 읽은 다음 AND인지 OR인지 확인하는 방식**이 덜 헷갈렸다.

조건이 더 복잡해지면 괄호를 사용해서 어떤 조건끼리 먼저 묶이는지 명확하게 적는 습관도 필요하다.

---

## 5. 범위를 직접 두 번 비교하지 않는 방법

가격이 5,000원 이상이면서 15,000원 이하인 상품을 찾는다면 비교식을 두 개 적어도 된다.

```sql
SELECT *
FROM products
WHERE price >= 5000
  AND price <= 15000;
```

같은 의미를 `BETWEEN`으로 더 짧게 표현할 수 있다.

```sql
SELECT *
FROM products
WHERE price BETWEEN 5000 AND 15000;
```

여기서는 양 끝값도 범위에 포함된다.

반대로 그 범위에 속하지 않는 값만 보고 싶다면 `NOT BETWEEN`을 붙일 수 있다.

```sql
SELECT *
FROM products
WHERE price NOT BETWEEN 5000 AND 15000;
```

내 기준으로는 `BETWEEN`을 **연속된 구간 하나를 검사할 때 읽기 쉽게 만드는 표현**으로 기억했다.

---

## 6. 여러 후보 중 하나와 일치하는지 확인하기

상품 이름이 몇 개의 후보 가운데 하나인지를 찾을 때 `OR`를 계속 이어 붙일 수도 있다.

```sql
SELECT *
FROM products
WHERE name = '갤럭시'
   OR name = '아이폰'
   OR name = '에어팟';
```

하지만 비교 대상이 많아질수록 문장이 길어진다.

이럴 때 `IN`을 사용하면 후보 목록을 한곳에 모을 수 있다.

```sql
SELECT *
FROM products
WHERE name IN ('갤럭시', '아이폰', '에어팟');
```

목록에 있는 값을 제외하려면 `NOT IN`을 사용한다.

```sql
SELECT *
FROM products
WHERE name NOT IN ('갤럭시', '아이폰', '에어팟');
```

내가 구분한 기준은 이렇다.

- 연속된 숫자 범위라면 `BETWEEN`
- 정해진 여러 후보 중 하나를 찾는다면 `IN`

둘 다 긴 조건식을 줄여주지만 사용하는 상황은 다르다.

## 7. 문자열 전체를 몰라도 찾는 방법

`=`은 문자열 전체가 정확히 같아야 한다.

그런데 이메일 앞부분만 기억하거나 주소에 특정 단어가 들어가는 데이터만 찾고 싶다면 정확한 일치만으로는 부족하다.

이때 `LIKE`와 와일드카드를 함께 사용한다.

### `%` : 길이에 상관없이 여러 문자를 허용

```sql
SELECT *
FROM customers
WHERE email LIKE 'sejong%';
```

위 조건은 `sejong`으로 시작하는 문자열을 찾는 형태다.

패턴 위치에 따라 의미가 달라진다.

```text
sejong%        → sejong으로 시작
%@example.com  → @example.com으로 끝남
%서울%          → 중간 어디든 '서울'이 포함됨
```

### `_` : 문자 한 자리와 대응

`_`는 정확히 한 글자 위치를 대신하는 패턴으로 사용할 수 있다.

예를 들어 다음과 같은 형태로 특정 길이와 위치를 가진 문자열을 찾을 수 있다.

```sql
WHERE name LIKE '이_신'
```

반대 조건은 `NOT LIKE`로 작성한다.

```sql
SELECT *
FROM customers
WHERE address NOT LIKE '서울특별시%';
```

`LIKE`는 편리하지만, 내가 느낀 한계는 **정확히 일치하는 값을 찾는 조건보다 범위가 넓어질 수 있다는 점**이다.

특히 앞부분까지 `%`로 시작하는 패턴은 데이터가 많을수록 검색 비용을 생각해야 하므로, 무조건 편하다는 이유만으로 남용하기보다는 필요한 검색인지 먼저 판단하는 편이 좋다.

---

## 8. 조회 결과의 순서는 따로 정해야 한다

데이터를 조회했다고 해서 내가 원하는 순서로 자동 정렬되는 것은 아니다.

가입 날짜나 가격처럼 특정 기준으로 결과의 순서를 정하고 싶다면 `ORDER BY`를 사용한다.

```sql
SELECT *
FROM customers
ORDER BY join_date ASC;
```

정렬 방향은 두 가지로 나눌 수 있다.

- `ASC` : 작은 값에서 큰 값으로 정렬
- `DESC` : 큰 값에서 작은 값으로 정렬

`ASC`는 기본값이라 생략할 수도 있다.

상품 가격이 높은 것부터 보고 싶다면 다음과 같이 적는다.

```sql
SELECT *
FROM products
ORDER BY price DESC;
```

내가 기억할 때는 `DESC`만 특별히 표시해야 하는 경우가 많다고 생각하면 편했다.

---

## 9. 정렬 기준이 겹치면 두 번째 기준을 추가한다

하나의 컬럼만으로 정렬하면 값이 같은 데이터끼리는 내가 원하는 순서를 만들지 못할 수 있다.

예를 들어 먼저 재고가 많은 상품을 위로 올리고, 재고 수량이 같다면 더 저렴한 상품을 먼저 보고 싶다고 하자.

```sql
SELECT *
FROM products
ORDER BY stock_quantity DESC, price ASC;
```

앞에 적은 컬럼이 1차 기준이고, 그 값이 같은 경우 다음 컬럼이 추가 기준으로 사용된다.

그래서 다중 정렬은 **앞에서부터 우선순위를 적용한다**고 생각하면 이해하기 쉽다.

---

## 10. 결과를 필요한 개수만 잘라서 가져오기

조회 결과가 아주 많더라도 항상 전부 필요한 것은 아니다.

예를 들어 가격이 가장 높은 상품 두 개만 보고 싶다면 먼저 가격순으로 정렬하고, 그 결과에서 두 개만 가져오면 된다.

```sql
SELECT *
FROM products
ORDER BY price DESC
LIMIT 2;
```

여기서 내가 중요하다고 본 부분은 `LIMIT` 자체보다 **어떤 순서에서 잘라내는지**다.

`ORDER BY` 없이 단순히 `LIMIT 2`만 사용하면 '상위 2개'라는 의미가 명확하지 않다.

따라서 가장 비싼 상품, 가장 최근 가입자처럼 순위의 의미가 필요한 경우에는 먼저 정렬 기준을 정하고 그다음 개수를 제한해야 한다.

---

## 11. 앞부분을 건너뛰고 다음 묶음을 가져오기

`LIMIT`에는 앞에서 몇 행을 건너뛸지도 지정할 수 있다.

```sql
LIMIT offset, row_count;
```

예를 들어 두 개씩 데이터를 보여준다고 하면 다음처럼 나눌 수 있다.

```sql
-- 첫 번째 묶음
SELECT *
FROM products
LIMIT 0, 2;
```

```sql
-- 두 번째 묶음
SELECT *
FROM products
LIMIT 2, 2;
```

```sql
-- 세 번째 묶음
SELECT *
FROM products
LIMIT 4, 2;
```

이 방식은 웹 페이지에서 결과를 여러 페이지로 나누는 페이징과 연결해서 이해할 수 있다.

내가 정리한 기준은 다음과 같다.

```text
offset     → 앞에서 몇 행을 넘길지
row_count  → 그 다음 몇 행을 가져올지
```

다만 페이지가 정확히 같은 기준으로 이어지게 하려면 조회 결과의 순서도 일정해야 하므로, 실제로는 `ORDER BY`와 함께 사용하는 흐름을 생각하는 것이 좋다.

## 12. 조회문을 읽는 나만의 순서

이번 내용에서 문법을 각각 외우는 것보다 아래 흐름으로 읽는 것이 더 이해하기 쉬웠다.

```text
SELECT    → 어떤 컬럼을 보여줄지
FROM      → 어느 테이블에서 가져올지
WHERE     → 어떤 행만 남길지
ORDER BY  → 결과를 어떤 기준으로 배치할지
LIMIT     → 최종적으로 몇 행을 가져올지
```

예를 들어 다음 쿼리를 보면,

```sql
SELECT name, price
FROM products
WHERE price >= 5000
ORDER BY price DESC
LIMIT 3;
```

나는 다음처럼 해석했다.

> products에서 가격이 5,000원 이상인 상품만 남긴 뒤,  
> 가격이 높은 순서로 정렬하고,  
> 그중 앞의 세 상품에 대해 이름과 가격만 보여준다.

결국 조회문은 명령어를 하나씩 따로 외우는 것보다 **원하는 결과를 단계적으로 좁혀가는 과정**으로 이해하는 편이 훨씬 자연스럽다.

## 13. 반복해서 나오는 값을 한 번만 보기

조회 결과에 같은 값이 여러 번 나타날 때가 있다.

예를 들어 주문한 고객 번호를 그대로 조회하면, 같은 고객이 여러 번 주문한 경우 고객 번호도 여러 번 나온다.

```sql
SELECT customer_id
FROM orders;
```

이 결과는 주문 기록을 그대로 보여주는 것이기 때문에 중복이 생길 수 있다.

만약 내가 보고 싶은 것이 **주문한 고객 번호의 종류**라면 `DISTINCT`를 사용할 수 있다.

```sql
SELECT DISTINCT customer_id
FROM orders;
```

이렇게 하면 같은 고객 번호가 여러 번 있더라도 결과에는 한 번만 나타난다.

내가 기억한 방식은 다음과 같다.

> `DISTINCT`는 조회 결과에서 같은 값을 반복해서 보여주지 않고 한 번씩만 남길 때 사용한다.

### 여러 컬럼을 함께 확인하는 경우

`DISTINCT`는 컬럼 하나뿐 아니라 여러 컬럼과도 함께 사용할 수 있다.

예를 들어 고객 번호와 상품 번호를 함께 조회하면서 같은 조합이 반복되는 것을 없애고 싶다면 다음처럼 작성할 수 있다.

```sql
SELECT DISTINCT customer_id, product_id
FROM orders;
```

이 경우에는 `customer_id` 하나만 보는 것이 아니라  
**고객 번호와 상품 번호를 묶은 조합 전체**를 기준으로 중복을 판단한다.

즉 고객 번호가 같아도 상품 번호가 다르면 서로 다른 결과로 남는다.

## 14. 일반 값처럼 비교할 수 없는 NULL

데이터를 조회하다 보면 어떤 컬럼에 값이 들어 있지 않은 경우가 있다.

SQL에서는 이런 상태를 `NULL`로 표현한다.

처음에는 `0`이나 빈 문자열과 비슷하게 보일 수 있지만 서로 다르다.

```text
0   → 숫자 0이 들어 있음
''  → 비어 있는 문자열이 들어 있음
NULL → 일반적인 값이 들어 있지 않은 상태
```

### NULL은 `=`로 비교하지 않는다

예를 들어 설명이 없는 상품을 찾는다고 해서 다음처럼 작성하면 원하는 결과가 나오지 않는다.

```sql
SELECT *
FROM products
WHERE description = NULL;
```

`NULL`은 일반 값처럼 `=`를 사용해서 비교하지 않는다.

대신 `IS NULL`을 사용한다.

```sql
SELECT *
FROM products
WHERE description IS NULL;
```

반대로 설명이 들어 있는 상품만 찾고 싶다면 `IS NOT NULL`을 사용한다.

```sql
SELECT *
FROM products
WHERE description IS NOT NULL;
```

나는 여기서 가장 중요한 부분을 다음처럼 정리했다.

```text
NULL 확인      → IS NULL
NULL이 아닌지 확인 → IS NOT NULL
```

즉 `NULL`을 확인할 때는 `=`이 아니라 `IS`를 사용한다고 기억하면 된다.

### MySQL에서 NULL이 정렬되는 위치

`description`처럼 `NULL`이 들어갈 수 있는 컬럼도 `ORDER BY`로 정렬할 수 있다.

MySQL에서는 `NULL`을 가장 작은 값처럼 처리한다.

그래서 오름차순으로 정렬하면 `NULL`이 먼저 나온다.

```sql
SELECT *
FROM products
ORDER BY description ASC;
```

반대로 내림차순으로 정렬하면 `NULL`은 뒤쪽에 나온다.

```sql
SELECT *
FROM products
ORDER BY description DESC;
```

정리하면 다음과 같다.

```text
ASC  → NULL이 앞쪽
DESC → NULL이 뒤쪽
```

### NULL 여부도 정렬 기준으로 사용할 수 있다

다음처럼 `description IS NULL`을 조회해 보면 `NULL` 여부에 따라 결과가 나뉘는 것을 확인할 수 있다.

```sql
SELECT *,
       description IS NULL
FROM products;
```

이 값을 `ORDER BY`의 기준으로 사용하는 것도 가능하다.

예를 들어 설명이 없는 상품을 먼저 보고, 그 다음 설명이 있는 상품을 내림차순으로 정렬하려면 다음처럼 작성할 수 있다.

```sql
SELECT *
FROM products
ORDER BY description IS NULL DESC,
         description DESC;
```

여기서는 첫 번째 정렬 기준으로 `NULL`인 행을 먼저 모으고,  
그 다음 `description` 값을 기준으로 다시 내림차순 정렬한다고 이해했다.
